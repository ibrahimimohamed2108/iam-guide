Cryptography for IAM\n\n### 1.1 Hashing Algorithms (Passwords & Integrity)\n\n#### Password Hashing Evolution\n\n**Legacy & Broken**:\n- `crypt()` - DES-based, 56-bit effective key (❌ **NEVER USE**)\n- `MD5`, `SHA-1` - Fast and weak (❌ **NEVER USE**)\n- `Bcrypt` - Salted, but slow iteration (⚠️ **Legacy**)\n\n**Modern & Recommended**:\n\n| Algorithm | Use Case | Cost Factor | Verify Time | Status |\n|-----------|----------|------------|------------|--------|\n| **Argon2id** | All new implementations | 3-4 | 40-50ms | ✅ **BEST** |\n| **scrypt** | High security needs | 15+ | 50-100ms | ✅ **Good** |\n| **PBKDF2** | Compliance required | 310,000+ | 30-60ms | ⚠️ **Accept** |\n| **bcrypt** | Legacy systems | 12+ | 100-200ms | ⚠️ **Legacy** |\n\n**Why Argon2id?**\n```\n✓ Memory-hard: Resistant to GPU/ASIC attacks\n✓ Time-hard: Can tune for speed/security tradeoff\n✓ Salted: Rainbow tables ineffective\n✓ Side-channel resistant: Constant-time implementation\n✓ Standard: NIST SP 800-63B recommended\n```\n\n**Argon2 Configuration**:\n```bash\n# Recommended settings (2024)\nargon2id \\\n  --memory=65540        # 64MB per password hash\n  --iterations=2        # 2 passes (tunable)\n  --parallelism=4       # 4 parallel threads\n  --hash-length=32      # 256-bit output\n  --salt-length=16      # 128-bit random salt\n```\n\n**Implementation Example** (Go):\n```go\nimport \"golang.org/x/crypto/argon2\"\n\nfunc hashPassword(password string) (string, error) {\n    salt := make([]byte, 16)\n    rand.Read(salt)\n    \n    hash := argon2.IDKey(\n        []byte(password),\n        salt,\n        2,           // time cost\n        65540,       // memory cost (64MB)\n        4,           // parallelism\n        32,          // key length\n    )\n    \n    // Encode salt + hash for storage\n    encoded := base64.StdEncoding.EncodeToString(\n        append(salt, hash...),\n    )\n    return encoded, nil\n}\n```\n\n### 1.2 Encryption for Secrets at Rest\n\n#### Key Derivation Functions (KDF)\n\n**Problem**: How to encrypt secrets without storing plaintext keys?\n**Solution**: Derive encryption key from password using KDF\n\n**KDF Comparison**:\n\n| KDF | Purpose | Key Length | Iterations | Notes |\n|-----|---------|-----------|------------|-------|\n| **HKDF** | Key expansion | Any | 1 | Fast, for derived keys |\n| **PBKDF2** | Password→key | 256-512 bit | 310k+ | Compliant, slower |\n| **scrypt** | Password→key | 256-512 bit | 15+ | Memory-hard, good |\n| **Argon2** | Password→key | 256-512 bit | 2-3 | Best option, new |\n\n**Example: Encrypting LDAP Binding Password**:\n```python\nfrom cryptography.hazmat.primitives.kdf.argon2 import Argon2\nfrom cryptography.hazmat.primitives.ciphers import Cipher, algorithms, modes\nimport os\n\nclass SecretManager:\n    def __init__(self, master_password: str):\n        # Derive encryption key from master password\n        kdf = Argon2(\n            memory_cost=65540,\n            time_cost=2,\n            parallelism=4,\n            hash_len=32,\n            salt=os.urandom(16),\n        )\n        self.key = kdf.derive(master_password.encode())\n    \n    def encrypt_secret(self, plaintext: str) -> str:\n        # Use AES-256-GCM for authenticated encryption\n        iv = os.urandom(12)  # 96-bit nonce\n        cipher = Cipher(\n            algorithms.AES(self.key),\n            modes.GCM(iv),\n        )\n        encryptor = cipher.encryptor()\n        ciphertext = encryptor.update(\n            plaintext.encode()\n        ) + encryptor.finalize()\n        \n        # Store: IV + ciphertext + tag\n        return base64.b64encode(\n            iv + ciphertext + encryptor.tag\n        ).decode()\n```\n\n### 1.3 Digital Signatures & Certificate Chains\n\n#### X.509 Certificate Validation Chain\n\n**Problem**: How do you know a certificate is legitimate?\n**Solution**: Follow the certificate chain to a trusted root CA\n\n**Certificate Chain Structure**:\n```\nRoot CA Certificate (Self-signed, trusted)\n    ↑ (signed by)\n    │\nIntermediate CA Certificate\n    ↑ (signed by)\n    │\nLeaf Certificate (example.com)\n```\n\n**Validation Steps**:\n```\n1. Verify leaf cert signature using Intermediate CA public key\n2. Verify Intermediate CA cert signature using Root CA public key\n3. Verify Root CA is in system trust store\n4. Check certificate validity dates (not expired)\n5. Check certificate CN/SAN matches domain\n6. Verify no certificate revocation (CRL or OCSP)\n7. Verify certificate key usage extensions\n```\n\n**Common Mistakes in IAM**:\n```bash\n# ❌ WRONG: Ignoring certificate validation\nldapsearch -x -H ldaps://ldap.example.com \\\n  -b \"dc=example,dc=com\" \"(uid=jdoe)\"\n# ^ Connects but doesn't verify certificate!\n\n# ❌ WRONG: Using self-signed without trust store\n# ^ Man-in-the-middle vulnerable\n\n# ✅ CORRECT: Explicit CA verification\nldapsearch -x -H ldaps://ldap.example.com \\\n  -b \"dc=example,dc=com\" \\\n  -d \"(uid=jdoe)\" \\\n  -D \"cn=admin,dc=example,dc=com\" \\\n  -y /etc/ldap/bind.pw \\\n  -Z \\\n  -E ca_cert_file=/etc/ssl/certs/ca-bundle.crt\n```\n\n**Certificate Pinning (Advanced)**:\n```python\n# Pin specific certificate for LDAP server\nimport ssl\nimport certifi\n\ncontext = ssl.create_default_context(\n    cafile=certifi.where()  # System CA bundle\n)\n\n# Pin specific certificate hash\nexpected_pin = \"sha256/AAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAA=\"\n\n# In production, verify pin matches actual cert\n# and update when certificate rotates\n```\n\n### 1.4 Symmetric vs Asymmetric Cryptography in IAM\n\n**Symmetric** (Shared Secret Key):\n- **Used for**: Encrypting secrets in database\n- **Example**: AES-256 encrypting LDAP bind password\n- **Problem**: Key distribution difficult\n- **Speed**: Fast (~1000x faster than asymmetric)\n\n**Asymmetric** (Public/Private Key Pair):\n- **Used for**: Digital signatures, certificate-based auth\n- **Example**: SSH key-based authentication\n- **Advantage**: Public key can be shared safely\n- **Speed**: Slow (~1000x slower than symmetric)\n\n**Hybrid Approach** (Practical IAM):\n```\n┌─────────────────────────────────────────┐\n│ 1. Use asymmetric crypto to establish   │\n│    shared symmetric key (TLS handshake) │\n├─────────────────────────────────────────┤\n│ 2. Use symmetric crypto for bulk        │\n│    encryption (fast, low overhead)      │\n├─────────────────────────────────────────┤\n│ 3. Example: LDAPS connection            │\n│    - TLS handshake (asymmetric)         │\n│    - Encrypt data with session key      │\n│      (symmetric AES-256)                │\n└─────────────────────────────────────────┘\n```\n\n---\n\n## 2. Advanced Authentication Methods\n\n### 2.1 Certificate-Based Authentication (Client Certificates)\n\n**When to Use**:\n- Machine-to-machine authentication\n- High-security administrative access\n- IoT device authentication\n- API authentication (in addition to OAuth2)\n\n**Implementation: LDAP with Client Certificates**\n\n```bash\n# 1. Generate client certificate\nopenssl req -new -x509 -days 365 \\\n  -keyout /etc/ssl/private/ldap-client.key \\\n  -out /etc/ssl/certs/ldap-client.crt \\\n  -subj \"/CN=ldap-admin\"\n\n# 2. Configure LDAP server for client cert auth\n# /etc/ldap/slapd.conf\nTLSCertificateFile /etc/ldap/certs/ldap-server.crt\nTLSCertificateKeyFile /etc/ldap/private/ldap-server.key\nTLSCACertificateFile /etc/ldap/certs/ca-bundle.crt\nTLSVerifyClient demand  # Require client certificate\n\n# 3. Connect with client certificate\nldapsearch -x -H ldaps://ldap.example.com \\\n  -b \"dc=example,dc=com\" \\\n  -Z \\\n  -E ca_cert_file=/etc/ssl/certs/ca-bundle.crt \\\n  -E cert_file=/etc/ssl/certs/ldap-client.crt \\\n  -E key_file=/etc/ssl/private/ldap-client.key \\\n  \"(uid=jdoe)\"\n```\n\n**Security Considerations**:\n- ✅ Strong authentication (certificate possession)\n- ✅ Works offline (no real-time validation needed)\n- ✅ Non-repudiation (can prove who made the request)\n- ⚠️ Key management complex (rotation, revocation)\n- ⚠️ CRL/OCSP latency (real-time revocation checking)\n\n### 2.2 Hardware Tokens (FIDO2/U2F)\n\n**How FIDO2 Works**:\n```\n┌─────────────┐\n│  User's PC  │\n│             │\n│ ┌─────────┐ │         ┌──────────┐\n│ │Browser  │ │         │IdP Server│\n│ └────┬────┘ │         └────┬─────┘\n│      │      │              │\n│  Hardware   │              │\n│  Token      │              │\n│ (FIDO2)     │              │\n└──────┬──────┘              │\n       │                     │\n       │─ Challenge ────────→│\n       │                     │\n       │← Signature ─────────│\n       │   (with counter)    │\n |\n|--------|---------|------|-------|\n| **Phishing resistant** | ❌ No | ❌ No | ✅ Yes |\n| **Works offline** | ❌ | ✅ Yes | ✅ Yes |\n| **User experience** | Poor | Good | Excellent |\n| **Cost** | Included | Free | $15-50 |\n| **Enterprise ready** | ❌ | ✅ | ✅ |\n\n**FIDO2 Deployment Example**:\n```python\nfrom fido2.server import Fido2Server\nfrom fido2.webauthn import PublicCredentialDescriptor\n\nclass MFAManager:\n    def __init__(self, rp_id=\"example.com\"):\n        self.server = Fido2Server(\n            PublicCredentialDescriptor(\n                type=\"public-key\",\n                id=rp_id,\n                name=rp_id,\n                icon=\"https://example.com/icon.png\"\n            )\n        )\n    \n    def register_start(self, username: str):\n        # Generate registration challenge\n        registration_data, state = self.server.register_begin(\n            {\"id\": username.encode(), \"name\": username},\n            []\n        )\n        # Store state temporarily (expire in 5 minutes)\n        return registration_data, state\n    \n    def register_complete(self, \n                         username: str, \n                         response: dict, \n                         state: bytes):\n        # Verify FIDO2 response and store credential\n        credential = self.server.register_complete(\n            state,\n            response\n        )\n        # Save credential.credential_data to database\n        return credential\n```\n\n### 2.3 Passwordless Authentication Protocols\n\n**Four Threat Modeling & Attack Surfaces\n\n### 3.1 Attack Vectors on Identity Systems\n\n#### STRIDE Threat Model Applied to IAM\n\n```\nS - Spoofing Identity\n    ├─ Compromise credentials (phishing, keylogger)\n    ├─ Replay attacks (capture and resend auth token)\n    ├─ Session hijacking (steal session cookie)\n    └─ Certificate theft (compromise CA)\n\nT - Tampering with Data\n    ├─ Modify LDAP directory entries\n    ├─ Alter audit logs (cover tracks)\n    ├─ Intercept LDAP bind password (MITM)\n    └─ Modify role assignments\n\nR - Repudiation\n    ├─ Admin denies making access change\n    ├─ No audit trail of privilege elevation\n    ├─ Logs are not tamper-proof\n    └─ No digital signatures on sensitive operations\n\nI - Information Disclosure\n    ├─ Enumerate LDAP directory via anonymous bind\n    ├─ Extract password hashes from database\n    ├─ Read credentials from memory\n    ├─ Intercept OAuth2 tokens (unencrypted)\n    └─ PII in audit logs\n\nD - Denial of Service\n    ├─ Directory server overload (unbounded LDAP queries)\n    ├─ Password lockout attacks (account enumeration)\n    ├─ Token revocation infrastructure overwhelmed\n    ├─ Replication failures (no failover)\n    └─ MFA bypass (all verification methods offline)\n\nE - Elevation of Privilege\n    ├─ Weak authorization logic (RBAC bypass)\n    ├─ Privilege inheritance bugs\n    ├─ Service account compromise→lateral movement\n    ├─ SoD violations (single user both creator+approver)\n    └─ Directory object permissions misconfigured\n```\n\n**Real-World Example: Privilege Escalation Chain**\n```\n1. Start: Standard user account\n   └─ Permissions: Read own files only\n\n2. Find: Over-permissioned group membership\n   └─ User is member of \"Developers\" group\n\n3. Check: Developers group permissions\n   └─ Has read access to /var/www/html source code\n\n4. Discover: Credentials hardcoded in source code\n   └─ Database admin password in config file\n\n5. Compromise: Database admin account\n   └─ Access to customer data\n\n6. Escalate: Database role has DBA permissions\n   └─ Can run stored procedures as SA\n\n7. Execute: xp_cmdshell to run OS commands\n   └─ Now have Windows server shell access\n\n8. Final: Windows account running database service\n   └─ Service account has admin rights (misconfigured)\n   └─ Can add self to Domain Admins group\n   └─ Full domain compromise\n```\n\n### 3.2 Common IAM Attack Patterns\n\n**Pattern 1: Credential Spray**\n```bash\n# Attacker has password list from breach\nfor password in $(cat /tmp/passwords.txt); do\n    for user in $(cat /tmp/users.txt); do\n        # Try authenticate as $user with $password\n        ldapwhoami -x -H ldap://ldap.example.com \\\n          -D \"uid=$user,ou=People,dc=example,dc=com\" \\\n          -w \"$password\" 2>/dev/null && \\\n          echo \"FOUND: $user:$password\"\n    done\ndone\n```\n\n**Pattern 2: Lateral Movement via Service Accounts**\n```bash\n# Found service account in /opt/app/.env\nSERVICE_ACCOUNT=app-api\nSERVICE_PASSWORD=SecurePassword123\n\n# Service account likely has delegated permissions\nldapsearch -x -H ldap://ldap.example.com \\\n  -D \"uid=$SERVICE_ACCOUNT,ou=Services,dc=example,dc=com\" \\\n  -w \"$SERVICE_PASSWORD\" \\\n  -b \"dc=example,dc=com\" \\\n  \"(&(uid=admin*)(employeeType=*))\" cn mail\n# ^ Found admin account email, now target for phishing\n```\n\n**Pattern 3: Directory Enumeration (Reconnaissance)**\n```bash\n# Check if anonymous bind allowed\nldapwhoami -x -H ldap://ldap.example.com\n\n# If successful, enumerate all users\nldapsearch -x -H ldap://ldap.example.com \\\n  -b \"ou=People,dc=example,dc=com\" \\\n  \"(objectClass=inetOrgPerson)\" uid mail telephoneNumber\n\n# Enumerate all groups and members\nldapsearch -x -H ldap://ldap.example.com \\\n  -b \"ou=Groups,dc=example,dc=com\" \\\n  \"(objectClass=groupOfNames)\" cn member\n```\n\n---\n\n## 4. Kerberos Deep Dive\n\n### 4.1 Kerberos Protocol Flow\n\n**Why Kerberos?**\n- Single source of truth (KDC)\n- No password sent over network\n- Tickets have expiration (time-based revocation)\n- Mutual authentication (client→server→client)\n- Works across network boundaries (realms)\n\n**Step-by-Step Protocol**:\n\n```\n┌──────────┐           ┌─────┐           ┌────────┐\n│  Client  │           │ KDC │           │ Server │\n│(Workstation)         │     │           │ (Web)  │\n└────┬─────┘           └──┬──┘           └───┬────┘\n     │                    │                   │\n1.   │─ AS-REQ (TGT request)\n     │   - Username\n     │   - Computer name\n     │────────────────────→\n     │\n2.   │   ← AS-REP (TGT response)\n     │     - TGT (encrypted with user's password hash)\n     │     - Ticket-granting key\n     │‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾\n     │\n3.   │─ TGS-REQ (Service ticket request)\n     │   - TGT\n     │   - Service name (HTTP/web.example.com)\n     │────────────────────→\n     │\n4.   │   ← TGS-REP (Service ticket)\n     │     - Service ticket (encrypted with service key)\n     │‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾\n     │\n5.   │─ AP-REQ (Access request with ticket)\n     │   - Service ticket\n     │   - Authenticator (encrypted timestamp)\n     │───────────────────────────────────────→\n     │\n6.   │   ← AP-REP (Access granted)\n     │     - Mutual auth proof\n     │     - Session key for encryption\n     │‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾\n     │\n7.   │─────── Authenticated communication ──────→\n     │        (encrypted with session key)\n```\n\n### 4.2 Kerberos Attack Vectors\n\n**Pass-the-Hash Attack** (Windows Kerberos)\n```\n1. Attacker compromises workstation\n2. Extracts cached TGT from memory (hashes)\n3. Uses TGT to obtain service tickets without password\n4. Impersonates user to access network resources\n\nMitigation:\n- Enable Kerberos armoring (FAST)\n- Enforce machine account passwords\n- Monitor unusual TGT requests\n- Use group policy to restrict token reuse\n```\n\n**Kerberoasting Attack**\n```\n1. Attacker has low-privilege domain user\n2. Request service ticket for service account\n   (any domain user can request!)\n3. Extract ticket from memory\n4. Offline brute-force ticket encryption\n   (encrypted with service account password)\n5. Compromise service account\n\nMitigation:\n- Use strong (random) passwords for service accounts\n- Use Group Managed Service Accounts (gMSA)\n- Monitor TGS-REQ for unusual patterns\n- Rotate service account passwords frequently\n```\n\n**Forged Ticket Attack** (Golden Ticket)\n```\n1. Attacker compromises KRBTGT password hash\n2. Creates fake TGT (signed with KRBTGT key)\n3. Uses forged TGT to obtain any service ticket\n4. Full domain compromise\n\nMitigation:\n- Monitor for unsigned/badly-signed tickets\n- Enable ticket validation (Kerberos armoring)\n- Regular KRBTGT password rotation\n- Check SID history manipulation\n- Monitor unusual ticket requests (times, resources)\n```\n\n---\n\n## 5. Compromise Assessment & Incident Response\n\n### 5.1 Signs of Identity System Compromise\n\n**Directory Server (LDAP/AD) Compromise Indicators**:\n\n```\n🚨 CRITICAL - Immediate Action Required:\n\n1. Unusually high query volume\n   └─ Possible: Mass enumeration or data exfiltration\n   └─ Log: \"INFO [cn=admin...]: Performed 10,000 searches\"\n   └─ Check: Query patterns, bind failures, anonymous binds\n\n2. Modification of directory entries\n   └─ Possible: Privilege escalation, access grant changes\n   └─ Log: \"cn=admin,dc=example,dc=com modified cn=jdoe\"\n   └─ Check: memberOf changes, role modifications\n\n3. Unusual bind activity\n   └─ Possible: Brute force, credential stuffing\n   └─ Log: Multiple BIND failures with same username\n   └─ Check: Failed binds > 5 per account per hour\n\n4. Replication failures\n   └─ Possible: Attacker severing replication to hide changes\n   └─ Log: \"Replication failed: Connection timeout\"\n   └─ Check: Replication status, network connectivity\n\n5. ACL modifications\n   └─ Possible: Creating backdoor accounts, permission escalation\n   └─ Log: \"ACL modified by cn=admin,dc=example,dc=com\"\n   └─ Check: Any ACL changes, especially anonymous access\n```\n\n**IAM/OAuth2 Compromise Indicators**:\n\n```\n🚨 CRITICAL - Immediate Action Required:\n\n1. Token issuance anomalies\n   └─ Possible: Token generation compromise\n   └─ Check: Tokens for wrong audiences, expired at issuance\n   └─ Metric: Tokens issued > 2x normal rate\n\n2. Unusual token usage patterns\n   └─ Possible: Compromised token being used\n   └─ Check: Token used from 3 countries in 1 hour (impossible travel)\n   └─ Check: Token used after owner change password\n   └─ Check: Token used at 3 AM when user never works then\n\n3. Signing key compromise\n   └─ Possible: CRITICAL - attacker can forge any token\n   └─ Check: Tokens with invalid signatures accepted\n   └─ Action: Immediate key rotation + revocation\n\n4. MFA bypass\n   └─ Possible: MFA infrastructure compromise\n   └─ Check: Successful authentications without MFA\n   └─ Check: Disabled MFA for high-value accounts\n   └─ Check: MFA service unavailability (attacker DoS)\n\n5. Unexpected scope grants\n   └─ Possible: Application compromised requesting extra permissions\n   └─ Check: App requesting admin scopes\n   └─ Check: Consent grants for sensitive resources\n```\n\n### Advanced RBAC: Constraints & SoD (Static and Dynamic)\n\n### 7.1 Static SoD Implementation\n\n**Problem**: How do you prevent conflicting role assignments?\n\n**Solution 1: Prevention at Grant Time**\n```python\nclass RoleManager:\n    SOD_RULES = {\n        \"PaymentCreator\": [\"PaymentApprover\"],\n        \"DataOwner\": [\"DataAuditor\"],\n        \"BackupAdmin\": [\"RestoreAdmin\"],\n        \"CodeAuthor\": [\"CodeReviewer\"],\n    }\n    \n    def can_assign_role(self, user_id: str, role: str) -> bool:\n        # Check what roles user currently has\n        current_roles = self.get_user_roles(user_id)\n        \n        # Check if new role conflicts\n        for existing_role in current_roles:\n            if existing_role in self.SOD_RULES.get(role, []):\n                return False  # Conflict detected!\n        \n        return True  # Safe to assign\n    \n    def assign_role(self, user_id: str, role: str) -> bool:\n        if not self.can_assign_role(user_id, role):\n            raise SoD Exception(f\"Cannot assign {role} to {user_id}\")\n        \n        # Proceed with assignment\n        self.db.execute(\n            \"INSERT INTO role_assignments (user_id, role) VALUES (?, ?)\",\n            (user_id, role)\n        )\n        \n        # Log for compliance\n        self.audit_log(\n            action=\"role_assignment\",\n            user=user_id,\n            role=role,\n            timestamp=datetime.now(),\n        )\n        return True\n```\n\n**Solution 2: Preventive Control with Exceptions**\n```python\nclass SoDManager:\n    def grant_exception(\n        self,\n        user_id: str,\n        conflicting_roles: List[str],\n        reason: str,\n        approver: str,\n        duration_days: int = 30,\n    ) -> bool:\n        \"\"\"Grant temporary exception to SoD rule\"\"\"\n        \n        # Validate exception reason\n        if not self._validate_reason(reason):\n            raise ValueError(\"Invalid exception reason\")\n        \n        # Create exception record with expiration\n        exception_id = self.db.execute(\n            \"\"\"\n            INSERT INTO sod_exceptions \n            (user_id, roles, reason, approver, expiration)\n            VALUES (?, ?, ?, ?, ?)\n            \"\"\",\n            (\n                user_id,\n                json.dumps(conflicting_roles),\n                reason,\n                approver,\n                datetime.now() + timedelta(days=duration_days),\n            )\n        ).lastrowid\n        \n        # Send notification to compliance team\n        self.notify_compliance_team(\n            f\"SoD exception {exception_id} granted for {user_id}\"\n        )\n        \n        # Set reminder to review/revoke\n        self.schedule_review(exception_id, duration_days - 5)\n        \n        return True\n    \n    def auto_revoke_expired(self):\n        \"\"\"Automatically revoke expired SoD exceptions\"\"\"\n        expired = self.db.execute(\n            \"SELECT * FROM sod_exceptions WHERE expiration < NOW()\"\n        )\n        for exception in expired:\n            user_id = exception['user_id']\n            roles = json.loads(exception['roles'])\n            \n            # Remove conflicting roles\n            for role in roles:\n                self.db.execute(\n                    \"DELETE FROM role_assignments WHERE user_id=? AND role=?\",\n                    (user_id, role),\n                )\n            \n            # Log the revocation\n            self.audit_log(\n                action=\"exception_revoked\",\n                user=user_id,\n                reason=\"Expiration\",\n            )\n```\n\n### 7.2 Dynamic SoD (Context-Based)\n\n**Scenario**: Allow conflicting roles but enforce separation at runtime\n\n```python\nclass DynamicSoD:\n    def check_operation_access(\n        self,\n        user_id: str,\n        resource: str,\n        operation: str,\n        context: dict,\n    ) -> bool:\n        \"\"\"Dynamically check if user can perform operation\"\"\"\n        \n        user_roles = self.get_user_roles(user_id)\n        \n        # Check if user has creator AND approver roles\n        if \"PaymentCreator\" in user_roles and \\\n           \"PaymentApprover\" in user_roles:\n            \n            # Allow only if conditions met\n            if operation == \"approve_payment\":\n                payment = self.get_payment(resource)\n                \n                # Rule 1: Cannot approve own payment\n                if payment['creator_id'] == user_id:\n                    return False\n                \n                # Rule 2: Require secondary approval if over threshold\n                if payment['amount'] > 100000:\n                    if context.get('secondary_approver') != True:\n                        return False\n                \n                # Rule 3: Require 24h separation\n                if datetime.now() - payment['created_at'] < timedelta(hours=24):\n                    return False\n            \n            return True\n        \n        # No conflict, proceed with normal authz check\n        return self.check_authorization(user_id, resource, operation)\n```\n\n---\n\n## 8.
