You need all 4 for complete security.\n\n---\n\n## 📋 Core Concepts Cheat Sheet\n\n### Identity\n- **What**: Digital representation of a user, service, or device\n- **Stored in**: Directory (LDAP/AD)\n- **Example**: john.doe@example.com, api-service-prod\n\n### Authentication (AuthN)\n- **What**: Proving who you are\n- **Methods**: Password, MFA, FIDO2, Certificate, Kerberos\n- **Best Practice**: MFA minimum, Passwordless preferred for admins\n\n### Authorization (AuthZ)\n- **What**: What you're allowed to do\n- **Models**: ACL (old), RBAC (common), ABAC (advanced), ReBAC (modern)\n- **Key**: Start with RBAC, add ABAC for conditions\n\n### Directory\n- **What**: Centralized identity storage\n- **Types**: LDAP (Linux), AD (Windows), Cloud (Azure/Okta)\n- **Purpose**: Single source of truth for identities and groups\n\n### Governance\n- **What**: Managing identity lifecycle\n- **Processes**: Joiners (create) → Movers (update) → Leavers (disable)\n- **Key**: Automation reduces errors\n\n---\n\n## 🛡️ Five Golden Rules\n\n### 1️⃣ **Least Privilege**\nGrant minimum access to do the job. Nothing more.\n```\nWrong:  Role = \"Finance\" (access everything)\nRight:  Role = \"Invoice_Approver\" (access invoices only)\n```\n\n### 2️⃣ **Separation of Duties**\nNo single person should both request AND approve.\n```\nMust Prevent:\n- Requester = Approver\n- Creator = Deleter (for critical data)\n- Auditor = Audited (system owner)\n```\n\n### 3️⃣ **Auditability**\nLog everything. Make logs immutable.\n```\nLog: Who, What, When, Where, Why\nKeep: 1-7 years per compliance\nEnsure: Centralized, searchable, linked to tickets\n```\n\n### 4️⃣ **Zero Trust**\nNever assume, always verify.\n```\nVerify on every request:\n- Is the user still valid?\n- Is the device compliant?\n- Is the network trusted?\n- Is the action suspicious?\n```\n\n### 5️⃣ **Automation**\nUse workflows instead of manual processes.\n```\nAutomate: Provisioning, Deprovisioning, Recertification, Policy Enforcement\nBenefit: Consistency, Speed, Auditability, Fewer Errors\n```\n\n---\n\n## 📚 Key Technologies Quick Reference\n\n### LDAP (OpenLDAP)\n| Aspect | Answer |\n|--------|--------|\n| **When to use** | Linux/Unix systems, open-source preference |\n| **Primary use** | Directory, authentication source |\n| **Security** | LDAPS/StartTLS for encryption |\n| **Admin tool** | ldapadd, ldapmodify, ldapsearch commands |\n| **Group model** | memberOf for group membership |\n| **Replication** | Provider/Consumer or multi-master |\n\n### Active Directory (AD)\n| Aspect | Answer |\n|--------|--------|\n| **When to use** | Windows environments, enterprise Windows |\n| **Primary use** | Directory, authentication, GPO, Kerberos |\n| **Security** | Kerberos (best), constrained delegation |\n| **Admin tool** | PowerShell, Active Directory Users & Computers |\n| **Group model** | AGDLP (Accounts→Global→Domain Local→Permissions) |\n| **Features** | GPO (policies), LAPS (password rotation), gMSA (service accounts) |\n\n### OAuth2 / OIDC (Modern IAM)\n| Aspect | Answer |\n|--------|--------|\n| **When to use** | SaaS, mobile apps, API protection |\n| **Primary use** | SSO, delegated auth, API tokens |\n| **Security** | Short-lived tokens, PKCE for mobile |\n| **Admin tool** | IdP console (Okta, Azure AD, Auth0, etc.) |\n| **Key concept** | Authorization Server issues tokens |\n| **Features** | MFA, Conditional Access, group claims |\n\n---\n\n## 🚀 Quick
